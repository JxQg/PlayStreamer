# 故障排查

本指南定位网络、媒体、OBS Studio（下文简称 OBS）和平台故障。首次连接见[快速开始](quick-start.md)。PS5 网络参数见 [PS5 设置](ps5-setup.md)。

## 运行诊断

前置条件：PlayStreamer 已保存连接设置。

1. 打开「设置与诊断」。
2. 点击「开始检查」。
3. 记录未通过检查的项目和错误原文。
4. 检查页面底部的「DNS 查询」和「直播域名命中」。
5. 按下一节选择故障现象。

「正在接收」表示应用已收到媒体流。「正在读取」表示读取客户端数，不识别 OBS。Bilibili 和 OOPZ 的输出仍需在接收端确认。

## 端口和防火墙

DNS（Domain Name System，域名系统）使用 TCP/UDP 53。RTMP（Real-Time Messaging Protocol，实时消息传输协议）接收使用 TCP 1935。

另一个 PlayStreamer、MediaMTX 或 Nginx RTMP 实例可能占用接收端口。本地 DNS 服务和代理软件也可能占用 53 端口。

警告：停止未知系统进程可能中断其他服务。端口冲突需要先确认进程用途，再调整监听配置。

1. 检查诊断中提示的冲突端口。
2. 确认占用端口的程序。
3. 按冲突软件文档调整监听或停止服务。
4. 确认 Windows 当前网络为可信的「专用网络」。
5. 在 PlayStreamer 中点击「配置防火墙」。
6. 如果 Windows 请求权限，完成权限确认。
7. 返回首页。
8. 点击「开启接收」或「重新开启接收」。

应用防火墙规则只允许指定 PS5 访问所选电脑地址。规则覆盖 DNS 和 RTMP，不包括其他代理端口。更换网卡、主机地址或安装路径后，需要重新核对规则。

## PS5 联网或 DNS 查询失败

1. 确认电脑已开机且未休眠。
2. 确认 PlayStreamer 显示「等待主机开播」或「正在接收」。
3. 核对 PS5 的「首选 DNS」与应用显示的电脑地址。
4. 核对 PS5 的「次选 DNS」为空或 `0.0.0.0`。
5. 核对应用中的 PS5 IPv4 地址。
6. 检查 PS5 与电脑是否位于同一 IPv4 子网。
7. 检查路由器是否启用了客户端隔离。
8. 按[端口和防火墙](#端口和防火墙)检查入站规则。

公共次选 DNS 可能绕过本地解析。访客 Wi-Fi 或不同子网也可能阻止 PS5 访问电脑。

## 检查原网络

1. 在 PS5 结束广播。
2. 将 PS5 的「DNS 设置」恢复为「自动」。
3. 运行 PS5 网络连接测试。
4. 如果测试仍失败，检查路由器和 PS5 的互联网出口。
5. 如果测试通过，按 [PS5 设置](ps5-setup.md#启动接收并修改-dns)恢复接流。

## 有查询但未收到广播

前置条件：PlayStreamer 的「DNS 查询」计数已增加。

1. 确认 PS5 已关联 Twitch。
2. 确认 PS5 当前选择 Twitch 广播。
3. 在 PS5 开始广播。
4. 检查 PlayStreamer 的「直播域名命中」。
5. 如果命中数为 0，按[TUN 和代理检查](#tun-和代理的检查顺序)检查解析。
6. 如果已有命中，检查 TCP 1935 和主机广播状态。
7. 按[版本与验证](validation.md)核对当前设备的接流结果。

域名命中只能证明 DNS 请求到达接流器。账号授权、媒体连接和主机广播状态仍需分别检查。

## 应用已接收但 OBS 黑屏

前置条件：PlayStreamer 显示「正在接收」。

1. 打开 OBS 媒体源属性。
2. 取消勾选「本地文件」。
3. 将「输入」设为 `rtmp://127.0.0.1:1935/live/playstation`。
4. 点击「确定」。
5. 如果仍黑屏，重新激活媒体源。
6. 检查 PlayStreamer 的媒体轨道。
7. 按 [OBS 设置](obs-platforms.md#检查本地录制)检查本地录制。

本地播放地址只用于同一台电脑上的媒体源。OBS 的「设置 → 直播」填写目标平台参数。

## OOPZ 有画面无声音

前置条件：OBS 已收到 PS5 音频，投影画面正常。

1. 检查 OBS 音频混音器中的 PS5 来源电平。
2. 按 [OBS 音频设置](obs-platforms.md#检查声音)设置监听设备。
3. 检查监听设备是否输出 PS5 声音。
4. 检查 OOPZ 的分享声音选项和输入设备。
5. 用另一账号或设备验证分享声音。

OBS 虚拟摄像头只提供视频。音频重复捕获或 OOPZ 回放进入共享时，可能产生叠音和回声。

## TUN 和代理的检查顺序

TUN 虚拟网卡和虚拟专用网络（VPN）需要保留局域网直连。物理网卡存在默认路由，不能证明 TUN 没有接管流量。

1. 确认应用选择物理以太网或 Wi-Fi 网卡。
2. 检查 TCP/UDP 53 和 TCP 1935 的监听。
3. 按代理产品文档调整冲突监听或 DNS 劫持规则。
4. 核对回环、电脑局域网地址、PS5 和所在网段的直连规则。
5. 检查直播入口是否返回电脑真实局域网地址。
6. 检查「上游 DNS」是否可达且不会指回本应用。
7. 如果本地接收正常但登录失败，检查 PS5 的联网出口。

虚拟地址应答（fake-IP）依赖匹配的流量转发路径。PS5 不一定具备电脑上的转发条件。上游 DNS 不接受 HTTP 或 SOCKS 代理端口。

复用电脑代理时，PS5 需要可达的 HTTP 或 mixed 监听端口。仅支持 SOCKS 的端口不适用。具体步骤见[代理共存说明](ps5-setup.md#与-tunvpn-和现有代理共存)。

## 无法关联 Twitch 时

本地 DNS 接流不替代 PSN 登录、Twitch 账号关联或广播授权。已关联账号仍可能在开播时访问平台。电脑能访问平台，不能证明 PS5 也能访问。

1. 在 PS5 验证 PSN 登录。
2. 在 PS5 验证 Twitch 账号关联。
3. 如果使用电脑代理，按[代理共存说明](ps5-setup.md#与-tunvpn-和现有代理共存)核对入口。
4. 在 PS5 验证 Twitch 开播。

项目尚无已验证的免登录原生广播方案。其他 OBS 输入来源见 [PS5 设置](ps5-setup.md#不使用-twitch-的选择)。

## 服务范围

| 服务 | 监听或使用范围 |
| --- | --- |
| DNS | 所选电脑地址的 TCP/UDP 53，仅接受指定 PS5 和本机诊断请求 |
| RTMP | TCP 1935 接收媒体流，固定地址供同机 OBS 播放 |
| 管理接口和鉴权服务 | 回环地址上的动态端口，无需向局域网或互联网放行 |
| Windows 防火墙规则 | 应用路径、所选电脑地址、指定 PS5 来源和「专用网络」 |

停止接收后，DNS 继续运行。完全退出、休眠或关机会停止 DNS。退出和修改网络的顺序见 [PS5 设置](ps5-setup.md#停止和恢复)。

## 导出诊断和反馈

诊断导出会脱敏媒体凭据。局域网地址和设备环境仍可能保留。

警告：公开账号凭据或直播密钥可能导致账号滥用。分享前必须检查诊断文件和截图。

1. 打开 PlayStreamer 的「设置与诊断」。
2. 点击「开始检查」。
3. 点击「导出」。

   系统在检查结果下方显示诊断文件路径。

4. 打开导出的诊断文件。
5. 检查文件和截图中的隐私信息。
6. 在 [GitHub Issues](https://github.com/JxQg/PlayStreamer/issues)提交反馈。

反馈信息包括：

- 应用版本和 Windows 版本。
- PS5 固件版本、OBS 版本和目标平台版本。
- 有线或 Wi-Fi 连接方式及代理使用情况。
- 复现步骤、预期结果和实际结果。
- 检查后的诊断文件和错误原文。
